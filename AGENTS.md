# RIG-puppy (噜噜) - AI Coding Agent Guide

## Project Overview

RIG-puppy (噜噜) is a desktop-level 5-DOF (five degrees of freedom) quadruped robotic dog platform based on ESP32-S3 and the XiaoZhi AI framework. It is designed for education, makers, and embedded AI enthusiasts.

### Key Features
- **Voice Interaction**: Custom wake word detection ("小陆同学"), natural language understanding
- **5-DOF Motion Structure**: 5 bus-style UART servos with a waist joint for rich movements (greeting, hugging, shaking hands, etc.)
- **Multimodal Interaction**: Integrated microphone, speaker, camera (GC0308), and LED meteor lights
- **AI Framework**: Deep integration with "小智" (XiaoZhi) open-source AI voice framework
- **Cloud Service**: Connects to xiaozhi.me official server, supports Qwen real-time model

### Hardware Specifications
- **Main Controller**: ESP32-S3 (N16R8 - 16MB Flash, 8MB PSRAM)
- **Audio**: MEMS microphone (INMP441), 8Ω 2W speaker (MAX98357A)
- **Display**: 1.09-inch round TFT SPI LCD (240×240)
- **Camera**: GC0308
- **IMU**: ICM42670 6-axis MEMS
- **Servos**: EM3 bus UART servos (5 units)
- **LED**: 70mm 3V meteor light strip

## Technology Stack

### Core Framework
- **ESP-IDF**: >= 5.4.0 (Espressif IoT Development Framework)
- **FreeRTOS**: Real-time operating system
- **C/C++**: Primary programming languages with C++ exceptions enabled

### Key Dependencies
- **Audio**: ESP-SR (speech recognition), esp-opus-encoder, esp_codec_dev
- **Display**: LVGL 9.2.2, esp_lvgl_port, various LCD drivers
- **Networking**: WebSocket/MQTT protocols, esp-wifi-connect
- **Camera**: esp32-camera
- **LED Control**: led_strip

### Project Version
Current version: `1.8.8` (defined in `CMakeLists.txt`)

## Build System

### Prerequisites
- ESP-IDF >= 5.4.0 installed and configured
- Python 3.x
- CMake >= 3.16

### Build Commands

```bash
# Set target (ESP32-S3 for RIG-puppy)
idf.py set-target esp32s3

# Configure project (menuconfig)
idf.py menuconfig

# Build the project
idf.py build

# Flash and monitor
idf.py flash monitor

# Merge binaries for release
idf.py merge-bin
```

Configure board type via `menuconfig`:

## Code Architecture

### Application Lifecycle

1. **Initialization** (`main.cc`)
   - Create FreeRTOS event loop
   - Initialize NVS flash
   - Launch Application singleton

2. **Application Startup** (`application.cc`)
   - Initialize board (hardware abstraction)
   - Setup audio codec, display, LED
   - Initialize network and protocols
   - Start main event loop

3. **State Machine**
   - `kDeviceStateStarting` → `kDeviceStateWifiConfiguring`/`kDeviceStateActivating`
   - `kDeviceStateIdle` → `kDeviceStateConnecting` → `kDeviceStateListening`/`kDeviceStateSpeaking`

### Key Components

#### Application Class (Singleton)
```cpp
class Application {
    static Application& GetInstance();
    void Start();
    void MainEventLoop();
    // Event-driven architecture with FreeRTOS event groups
};
```

#### Board Abstraction
- Base class: `Board` (`main/boards/common/board.h`)
- RIG-puppy implementation: `LuluEsp32S3Board` in `main/boards/lulu-esp32s3/`
- Board-specific features isolated per directory

#### XGO Motion Control
- `xgo.cc/h`: Low-level servo control via UART
- `xgo_action.cc/h`: High-level action definitions (15+ actions)
- Actions: Wave, Naughty, Lookup, Swing, Rolling, Angry, Swimming, Pee, Stretch, Bouncing, Shaking, Sit, Scratch, Hug

### Communication Protocol

The device supports multiple protocols for cloud communication:
- **WebSocket** (default): Real-time bidirectional communication
- **MQTT**: For IoT scenarios

See `docs/websocket.md` for detailed protocol specification.

#### MCP Protocol
- Model Context Protocol for IoT control
- JSON-RPC 2.0 based
- Supports tool discovery and invocation
- See `docs/mcp-protocol.md` and `docs/mcp-usage.md`

## Development Conventions

### Code Style
- Use C++11/14 features (exceptions enabled)
- Prefer `std::unique_ptr`/`std::shared_ptr` for memory management
- Use ESP-IDF logging macros: `ESP_LOGI`, `ESP_LOGW`, `ESP_LOGE`
- Error handling with `ESP_ERROR_CHECK()` for critical operations

### Configuration Management
- Hardware pins defined in `main/boards/<board>/config.h`
- Compile-time config via Kconfig (menuconfig)
- Runtime settings stored in NVS flash (`settings.cc`)

### GPIO Configuration (RIG-puppy)
```cpp
// Audio (Simplex I2S mode)
#define AUDIO_I2S_MIC_GPIO_WS   GPIO_NUM_1
#define AUDIO_I2S_MIC_GPIO_SCK  GPIO_NUM_2
#define AUDIO_I2S_MIC_GPIO_DIN  GPIO_NUM_42
#define AUDIO_I2S_SPK_GPIO_DOUT GPIO_NUM_39
#define AUDIO_I2S_SPK_GPIO_BCLK GPIO_NUM_40
#define AUDIO_I2S_SPK_GPIO_LRCK GPIO_NUM_41

// Display (SPI)
#define DISPLAY_BACKLIGHT_PIN GPIO_NUM_38
#define DISPLAY_MOSI_PIN      GPIO_NUM_20
#define DISPLAY_CLK_PIN       GPIO_NUM_19
#define DISPLAY_DC_PIN        GPIO_NUM_47
#define DISPLAY_RST_PIN       GPIO_NUM_21
#define DISPLAY_CS_PIN        GPIO_NUM_45

// Camera (DVP parallel interface)
// See main/boards/lulu-esp32s3/config.h for full pinout

// User Input
#define BOOT_BUTTON_GPIO      GPIO_NUM_0
#define BUILTIN_LED_GPIO      GPIO_NUM_48
```

### Adding New Actions
To add a new robot action:
1. Define action ID in `main/boards/lulu-esp32s3/xgo_action.h`
2. Implement action function in `main/boards/lulu-esp32s3/xgo_action.cc`
3. Add action to switch-case in `xgo_action()` function
4. Update action mapping in server-side configuration

## Deployment Process

### Firmware Update (OTA)
- OTA URL configured via `CONFIG_OTA_URL` (default: https://api.tenclass.net/xiaozhi/ota/)
- Automatic version check on startup
- Supports rollback on failure

### Flash Layout (16MB)
```
0x0000    - Bootloader
0x8000    - Partition Table
0x9000    - NVS (16KB)
0xD000    - OTA Data (8KB)
0xF000    - PHY Init (4KB)
0x10000   - Model Data (960KB)
0x100000  - App OTA0 (10.5MB)
0xB80000  - App OTA1 (4.5MB)
```

### First-Time Setup
1. Flash firmware: `idf.py flash`
2. Connect to WiFi via serial commands or acoustic provisioning
3. Activate device (get activation code from display/server)
4. Device ready for voice interaction

## Important Notes

### Memory Constraints
- Main task stack: 8192 bytes (configured in sdkconfig)
- PSRAM recommended for audio processing features
- Optimize for size (`CONFIG_COMPILER_OPTIMIZATION_SIZE=y`)

### Hardware Requirements
- ESP32-S3 with PSRAM mandatory for full features
- Some audio features (wake word, AFE) require PSRAM
- Custom wake word only supported on ESP32-S3/ESP32-P4 with PSRAM

## Common Issues

1. **Build fails with missing components**: Run `idf.py fullclean` and rebuild
2. **Wake word not working**: Ensure PSRAM is enabled and configured
3. **Audio quality issues**: Check I2S pin configuration in board config
4. **Display not working**: Verify LCD type selection in menuconfig matches hardware
